# D5. 담은 상품 보기 화면 구현

현재 구현 중인 코레일 지역상품 쇼핑 서비스에 **D5. 담은 상품 보기 화면**을 구현해줘.

이 화면은 사용자가 D3 상품상세 페이지 또는 D4 브랜드샵에서 장바구니에 추가한 상품을 한 번에 확인하고, 각 상품의 수량을 조정한 뒤 배송정보 입력 단계로 넘어가는 장바구니 화면이다.

첨부한 D5 레퍼런스 이미지를 전체적인 화면 구조와 상품 리스트 UI의 기준으로 참고해줘.

특히 레퍼런스의 다음 구조는 반드시 유지한다.

* 담은 상품 목록이 세로로 표시되는 구조
* 각 상품 왼쪽에 상품 이미지
* 이미지 오른쪽에 상품명과 가격
* 상품 오른쪽에 `− / 수량 / +` 컨트롤
* 상품 수량을 실제로 변경할 수 있는 구조

페이지는 상품이 많아질 경우 **세로 스크롤 가능**해야 한다.

---

# 1. D3 / D4와 D5 연결

D3 상품상세 페이지의

**장바구니**

버튼으로 담은 상품과,

D4 브랜드샵의 각 상품 오른쪽에 있는

**`+`**

버튼으로 담은 상품을 D5에서 확인할 수 있도록 한다.

D4의

**담은 상품 보기**

버튼을 클릭하면 D5로 이동한다.

예:

`/shop/cart`

기존에 D3와 D4에서 구현한 cart state를 그대로 사용하고, D5용 장바구니 데이터를 별도로 새로 만들지 말아줘.

즉,

D3에서 상품 A 담기
+
D4에서 상품 B 담기

→ D5에서 상품 A와 상품 B를 모두 확인

할 수 있어야 한다.

---

# 2. 전체 화면 구조

모바일 약 360~430px 너비를 기준으로 구현한다.

화면의 콘텐츠 순서는 다음과 같다.

1. 상단 뒤로가기
2. 화면 제목
3. 업체명 및 위치
4. 철도배송 안내
5. 담은 상품 개수
6. 담은 상품 리스트
7. 결제 예정 금액 영역
8. 총 결제 금액
9. 배송정보 입력하기 버튼

상품이 많아질 경우 5~9 영역까지 자연스럽게 아래로 이어지며 전체 페이지를 세로 스크롤할 수 있어야 한다.

---

# 3. 화면 제목

화면 가장 위에는 다음 제목을 표시한다.

# 담은 상품 보기

왼쪽에는 뒤로가기 버튼을 배치한다.

뒤로가기 버튼을 누르면 사용자가 직전에 보고 있던 D4 브랜드샵 또는 이전 페이지로 돌아가도록 한다.

---

# 4. 업체 정보

제목 아래에는 현재 장바구니 상품을 판매하는 업체명을 표시한다.

시연용 대표 업체:

**삼진어묵 부산역점**

그 아래에는 작은 글씨로 위치를 표시한다.

예:

📍 **부산역 3번 출구 도보 2분**

업체명은 위치보다 크게 표시한다.

---

# 5. 철도배송 안내

업체 정보 아래에는 D4와 동일한 디자인의 철도배송 안내 카드를 재사용해줘.

예:

🚄 **앱에서 주문하면 원하는 곳으로 철도배송 받을 수 있어요**

연한 코레일 블루 배경의 rounded card 형태로 구성한다.

D4에서 이미 RailwayDeliveryInfo 등의 컴포넌트를 만들었다면 새로 구현하지 말고 재사용한다.

---

# 6. 담은 상품 개수

배송 안내 아래에는 현재 장바구니에 담겨 있는 상품 종류의 개수를 표시한다.

예:

## 담은 상품 (3개)

또는 레퍼런스처럼

**담은 상품 (3개)**

형태로 보여준다.

장바구니에서 상품이 삭제되거나 추가되면 숫자도 자동으로 변경되어야 한다.

상품 종류가 3개이고 각각 수량이 2개인 경우에는 우선 상품 행의 개수를 기준으로 표시해도 된다.

즉,

상품 A × 2
상품 B × 1
상품 C × 1

이면

**담은 상품 (3개)**

로 표시한다.

---

# 7. 상품 리스트 기본 구조

상품 리스트는 첨부한 레퍼런스 이미지와 같은 세로형 구조를 사용한다.

각 상품 행은 다음 구조로 만든다.

**왼쪽**

상품 이미지

**가운데**

상품명
가격

**오른쪽**

삭제 버튼
`−  수량  +`

형태로 구성한다.

상품 사이에는 얇은 divider 또는 충분한 세로 간격을 사용한다.

---

# 8. 상품 이미지

각 상품의 왼쪽에는 정사각형 또는 rounded rectangle 형태의 상품 이미지를 배치한다.

D4에서 사용했던 상품 이미지 데이터를 그대로 사용해줘.

이미지는 약 70~90px 정도로 구성하고 모바일 화면에서 상품 정보보다 지나치게 크지 않게 한다.

---

# 9. 상품명과 가격

상품 이미지 오른쪽에는 상품명을 표시한다.

예:

**어묵 선물세트 1호**

그 아래에는 가격을 굵게 표시한다.

예:

**20,000원**

상품명은 최대 2줄 정도로 제한한다.

가격은 상품명 바로 아래에 배치한다.

---

# 10. 수량 조절 UI

각 상품 오른쪽에는 레퍼런스처럼 수량을 조절할 수 있는 stepper를 구현한다.

형태:

**−　1　+**

`−`와 `+`는 원형 버튼으로 만들어줘.

코레일 블루 계열을 사용한다.

### `+` 버튼

클릭할 때마다 상품 수량이 1 증가한다.

예:

1

→ `+`

→ 2

→ `+`

→ 3

### `−` 버튼

수량이 2 이상일 경우 클릭하면 1 감소한다.

예:

3

→ `−`

→ 2

수량은 최소 1로 제한한다.

수량이 1인 상태에서 `−`를 누르면 0으로 만들지 않는다.

---

# 11. 수량 변경에 따른 금액 계산

수량이 변경되면 결제 금액에도 즉시 반영되어야 한다.

예:

어묵 선물세트 1호

단가:

20,000원

수량:

1개

→ 20,000원

수량:

2개

→ 40,000원

으로 계산한다.

전체 상품의 수량과 금액을 합산해서 하단의 결제 예정 금액과 총 결제 금액을 실시간으로 업데이트한다.

UI 숫자만 변경되고 총 금액이 그대로 유지되는 방식으로 구현하지 말아줘.

---

# 12. 상품 삭제

레퍼런스처럼 상품 행 오른쪽 상단에 작은 `×` 버튼을 배치해줘.

사용자가 `×`를 누르면 해당 상품을 장바구니에서 삭제한다.

삭제 후

* 상품 리스트
* 담은 상품 개수
* 총 상품 금액
* 총 결제 금액

이 즉시 다시 계산되어야 한다.

필요하다면

**상품을 삭제했습니다.**

라는 작은 toast를 표시해도 된다.

---

# 13. 시연용 상품

D4의 삼진어묵 부산역점에서 사용한 상품을 그대로 연동한다.

예:

### 상품 1

상품명: 어묵 선물세트 1호
가격: 20,000원
수량: 1

### 상품 2

상품명: 프리미엄 어묵세트
가격: 28,000원
수량: 1

### 상품 3

상품명: 종합 선물세트
가격: 35,000원
수량: 1

초기 상태가 위와 같다면

총 상품 금액:

**83,000원**

이 되도록 한다.

---

# 14. 결제 예정 금액

상품 리스트 아래에는

## 결제 예정 금액

영역을 만든다.

이 영역에는 결제 금액의 세부 내역을 보여준다.

예:

**총 상품 금액　　　　　　　83,000원**

**할인 금액　　　　　　　　 -0원**

필요하면 추후 배송비가 확정되는 구조를 고려해

**배송비　　　　　　　　　배송정보 입력 후 계산**

같은 항목을 추가할 수 있다.

다만 현재 시연에서 필요하지 않다면 상품 금액과 할인 금액까지만 표시해도 된다.

---

# 15. 총 결제 금액

결제 예정 금액의 세부내역 아래에는 divider를 넣고 최종 결제 금액을 크게 표시한다.

예:

**총 결제 금액　　　　　　83,000원**

총 결제 금액은 일반 세부항목보다 굵고 크게 표현한다.

수량을 변경하거나 상품을 삭제하면 이 값도 즉시 변경되어야 한다.

예:

20,000원 상품을 1개 추가

83,000원

→

**103,000원**

---

# 16. 배송정보 입력하기

결제 금액 아래에는 다음 단계로 넘어가기 위한 큰 CTA 버튼을 배치한다.

버튼 문구:

**배송정보 입력하기**

필요하면 위치 또는 배송 관련 아이콘을 왼쪽에 추가할 수 있다.

예:

**📍 배송정보 입력하기**

버튼 디자인은

* 화면 너비 대부분 사용
* 진한 코레일 블루 배경
* 흰색 텍스트
* rounded rectangle

형태로 만든다.

화면에서 가장 강한 CTA가 되도록 표현한다.

---

# 17. 배송정보 입력하기 버튼 동작

사용자가

**배송정보 입력하기**

버튼을 누르면 다음 단계인 배송정보 입력 화면으로 이동해야 한다.

예:

D5
→ 배송정보 입력 화면

route 예:

`/shop/delivery-info`

또는 추후 구현할 D6 route를 사용한다.

아직 배송정보 입력 화면이 구현되지 않았다면 임시 화면을 만들어서 navigation이 정상적으로 작동하도록 한다.

버튼을 눌렀는데 아무 반응이 없는 상태로 만들지 말아줘.

---

# 18. 장바구니가 비어 있는 경우

사용자가 모든 상품을 삭제해서 장바구니가 비게 될 수도 있다.

이 경우 깨진 화면으로 두지 말고 empty state를 보여준다.

예:

## 담은 상품이 없습니다

**브랜드샵에서 원하는 상품을 담아보세요.**

버튼:

**상품 둘러보기**

클릭

→ 이전 브랜드샵 또는 D1 쇼핑 메인으로 이동

이 상태에서는

**배송정보 입력하기**

버튼을 비활성화한다.

---

# 19. 스크롤

이 화면은 반드시 세로 스크롤 가능해야 한다.

상품이 3개일 때뿐만 아니라 5개, 8개, 10개 이상 담기더라도 사용자가 아래로 스크롤해서 모든 상품을 확인할 수 있어야 한다.

특히 상품 목록이 길어졌을 때

* 결제 예정 금액
* 총 결제 금액
* 배송정보 입력하기

영역도 정상적으로 아래에서 확인할 수 있어야 한다.

레퍼런스처럼 하나의 모바일 장바구니 화면으로 자연스럽게 이어지도록 구현한다.

---

# 20. 배송정보 버튼 위치

D3의 `장바구니 / 바로 구매` 버튼과 달리 D5의

**배송정보 입력하기**

버튼은 반드시 화면에 fixed할 필요는 없다.

현재 D5에서는

상품 리스트
↓
결제 금액
↓
배송정보 입력하기

순서로 콘텐츠의 마지막에 나타나도록 구성한다.

즉 사용자가 상품과 결제금액을 확인한 뒤 다음 단계로 이동하는 흐름을 만든다.

---

# 21. Cart state 구조

D3, D4, D5가 동일한 cart state를 사용하도록 한다.

예:

```text
cartItems

- productId
- storeId
- productName
- price
- image
- selectedOption
- quantity
```

필요한 함수:

```text
addToCart(product)
increaseQuantity(productId)
decreaseQuantity(productId)
removeFromCart(productId)
calculateSubtotal()
```

기존 프로젝트에 이미 cart logic이 있다면 위 로직을 새로 중복 구현하지 말고 기존 구조를 확장하거나 재사용한다.

---

# 22. 금액 계산

금액은 다음과 같은 방식으로 계산한다.

```text
각 상품 금액 = 상품 단가 × 수량

총 상품 금액
= 모든 상품 금액 합계

총 결제 금액
= 총 상품 금액 - 할인 금액
```

추후 배송정보 단계에서 배송비가 추가될 수 있도록 구조는 확장 가능하게 만들어줘.

현재 D5에서는 임의의 배송비를 만들어 총액에 추가하지 말아줘.

---

# 23. 여러 업체 상품 처리

현재 시연의 대표 흐름은 **삼진어묵 부산역점 한 업체의 상품을 여러 개 담는 상황**을 우선 구현한다.

따라서 레퍼런스처럼 화면 상단에

**삼진어묵 부산역점**

을 한 번 표시하고 그 아래에 상품들을 보여준다.

다만 향후 서로 다른 업체의 상품이 한 장바구니에 들어올 가능성을 고려해서 cart data에는 `storeId`를 유지해줘.

향후에는 업체별 grouping이 가능하도록 데이터 구조만 확장 가능하게 만든다.

현재 D5 UI를 불필요하게 복잡한 다중 업체 장바구니 화면으로 바꾸지는 말아줘.

---

# 24. 디자인 방향

첨부한 D5 레퍼런스 이미지에서 다음 UI를 특히 참고한다.

### 제목

상단 중앙에

**담은 상품 보기**

### 업체 정보

업체명은 굵게

위치는 작은 회색 텍스트

### 철도배송 안내

연한 블루 rounded card

### 상품 리스트

각 상품마다

**상품 이미지 | 상품명·가격 | − 수량 +**

구조 유지

### 상품 이미지

둥근 정사각형

### 수량 버튼

파란색 원형 `−`, `+` 버튼

### 결제 영역

상품 목록과 명확하게 구분

# 26. 반드시 유지해야 하는 레퍼런스 구조

첨부한 D5 레퍼런스에서 다음 부분은 반드시 유지한다.

1. ‘담은 상품’ 영역 아래에 상품 리스트가 위치한다.
2. 상품 왼쪽에 상품 사진이 있다.
3. 상품 사진 오른쪽에 상품명이 있다.
4. 상품명 아래에 가격이 있다.
5. 상품 오른쪽에 현재 수량이 표시된다.
6. 수량 양옆에 `−`, `+` 버튼이 있다.
7. `+` 버튼을 누르면 수량이 실제 증가한다.
8. `−` 버튼을 누르면 수량이 실제 감소한다.
9. 상품 리스트 아래에 결제 금액이 표시된다.
10. 페이지가 세로 스크롤 가능하다.

# 27. 구현 완료 기준

다음 조건을 모두 확인해줘.

1. D4의 ‘담은 상품 보기’를 누르면 D5로 이동한다.
2. D3에서 장바구니에 담은 상품도 D5에 표시된다.
3. D4에서 `+`로 담은 상품도 D5에 표시된다.
4. D3, D4, D5가 동일한 cart state를 사용한다.
5. 화면 상단에 ‘담은 상품 보기’ 제목이 있다.
6. 업체명이 표시된다.
7. 업체 위치가 표시된다.
8. 철도배송 안내가 표시된다.
9. ‘담은 상품 (N개)’가 표시된다.
10. 각 상품 왼쪽에 이미지가 표시된다.
11. 각 상품의 상품명이 표시된다.
12. 각 상품 가격이 표시된다.
13. 각 상품에 `− / 수량 / +` 컨트롤이 있다.
14. `+` 버튼을 누르면 실제 수량이 증가한다.
15. `−` 버튼을 누르면 실제 수량이 감소한다.
16. 상품을 삭제할 수 있다.
17. 수량 변경 시 총 상품 금액이 즉시 변경된다.
18. 상품 삭제 시 총 금액이 즉시 변경된다.
19. 결제 예정 금액 영역이 있다.
20. 총 결제 금액이 강조되어 표시된다.
21. 맨 아래에 ‘배송정보 입력하기’ 버튼이 있다.
22. ‘배송정보 입력하기’를 누르면 다음 배송정보 화면으로 이동한다.
23. 상품이 많아지면 전체 화면을 세로 스크롤할 수 있다.
24. 장바구니가 비었을 때 empty state가 있다.
25. 약 360~430px 모바일 화면에서 UI가 깨지지 않는다.
26. 첨부한 D5 레퍼런스의 상품 리스트 정보 구조를 유지한다.

새 프로젝트를 만들지 말고 **현재 D1~D4가 구현되어 있는 코레일 쇼핑 프로젝트 내부에서 이어서 구현**해줘.

작업 시작 전에 기존

* router
* cart state
* D3 장바구니 기능
* D4 `+` 상품 담기 기능
* product mock data
* store mock data
* global style
* icon library

를 확인한다.

특히 D3, D4에서 이미 저장한 cart 데이터를 D5에서 그대로 읽도록 하고, D5를 위해 별도의 임시 상품 배열을 새로 만드는 방식은 사용하지 말아줘.

기존에 정상적으로 동작하는 D1~D4 화면은 불필요하게 수정하지 말아줘.

구현이 끝난 뒤 수량 증가, 수량 감소, 삭제, 금액 재계산, 페이지 이동을 직접 확인하고 build 또는 실행 과정에서 오류가 없는지까지 검사해줘.
