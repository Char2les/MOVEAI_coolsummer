# D2. 검색결과 화면

## 화면 이름 / ID

* **화면 ID:** D2
* **화면 이름:** 검색결과
* **서비스:** 코레일톡 쇼핑
* **화면 유형:** 상품 검색 및 비교 화면

---

# 1. 이 화면의 목적

D1 쇼핑 메인 화면에서 사용자가 검색한 키워드에 해당하는 **지역상품 검색결과를 확인하고, 정렬·필터링한 뒤 원하는 상품을 선택하는 화면**을 구현한다.

사용자는 이 화면에서 다음을 할 수 있어야 한다.

* 현재 검색어 확인
* 검색어 수정 및 재검색
* 검색된 상품 개수 확인
* 추천순 / 가격순 / 배송비순 / 도착 빠른순 정렬
* 배송조건 필터 적용
* 상품 카테고리 필터 적용
* 상품별 가격 및 배송조건 비교
* 원하는 상품 선택
* 선택한 상품의 상세정보 확인

이 화면의 가장 중요한 목적은 단순히 상품을 나열하는 것이 아니라,

**“상품 가격 + 철도배송 가능 여부 + 도착시간 + 배송비”**

를 한 화면에서 비교할 수 있도록 하는 것이다.

---

# 2. 진입 위치

## 기본 진입경로

**D1 쇼핑 메인**

→ 상단 검색창에 검색어 입력

→ 검색 실행

→ **D2 검색결과**

예시:

D1 검색창에

`어묵`

입력

→ 검색 실행

→ D2에서 `어묵` 검색결과 표시

D1에서 입력한 검색어를 D2로 전달하여 D2 검색창에도 그대로 표시한다.

---

# 3. D1에서 전달받아야 하는 정보

최소 다음 정보를 D2가 받을 수 있도록 한다.

* `searchQuery`

예:

`searchQuery = "어묵"`

실제 서버 검색 API는 필요하지 않다.

Mock 상품 데이터를 기준으로 프론트엔드에서 검색·정렬·필터 기능을 구현한다.

현재 프로젝트에 검색 상태 관리 방식이 존재한다면 기존 방식을 사용한다.

---

# 4. 화면 구성 순서

모바일 세로 화면 기준으로 위에서 아래 순서로 구성한다.

1. 상단 Header
2. 검색창
3. 1차 정렬 필터
4. 배송 관련 필터
5. 상품 카테고리 필터
6. 검색결과 개수 및 검색어
7. 상품 검색결과 리스트
8. 코레일톡 하단 Main Navigation

상품 검색결과가 많을 경우 전체 화면은 **세로 Scroll** 방식으로 작동해야 한다.

하단 Main Navigation은 기존 코레일톡 구조가 Fixed Navigation이라면 화면 하단에 고정한다.

---

# 5. 상단 Header

화면 최상단에 다음 요소를 표시한다.

### 왼쪽

`←`

뒤로가기 버튼

### 제목

**검색결과**

### 오른쪽

필터 또는 검색설정 아이콘

Reference Image의 우측 설정 형태 아이콘을 참고한다.

기존 프로젝트에 Header 컴포넌트가 존재하면 새로 만들지 말고 재사용한다.

---

# 6. 뒤로가기 인터랙션

사용자가 Header의 `←` 버튼을 누르면:

→ **D1 쇼핑 메인 화면으로 돌아간다.**

가능하면 사용자가 D1에서 입력했던 검색어 및 쇼핑 화면의 기존 상태를 유지한다.

예:

D1에서 `어묵` 검색

→ D2

→ 뒤로가기

→ D1 검색창에 `어묵`이 유지되도록 할 수 있다.

---

# 7. 검색창

Header 바로 아래에 **검색창을 크게 표시한다.**

D1에서 사용한 검색창과 동일하거나 최대한 유사한 디자인을 사용한다.

### 표시정보

D1에서 입력한 검색어를 그대로 표시한다.

예:

`어묵`

Reference Image처럼 검색창 왼쪽에 돋보기 아이콘을 배치한다.

오른쪽에는 검색어 삭제용:

`X`

버튼을 배치한다.

---

# 8. 검색창 인터랙션

검색창은 단순 표시용이 아니라 **D2에서도 다시 입력 가능한 검색창**이어야 한다.

### 검색어 수정

사용자가 기존 검색어를 삭제하고 다른 검색어를 입력할 수 있다.

예:

`어묵`

↓

`쿠키`

### 검색 실행

Enter 또는 검색 버튼 실행

→ 현재 D2에서 새로운 검색결과로 갱신

새 페이지를 중복 생성하지 않는다.

### X 버튼

검색어 전체 삭제

→ 검색 Input을 빈 상태로 만든다.

---

# 9. 검색창 예외상태

### 검색어가 없는 경우

검색어가 없는 상태에서 검색을 실행하면:

**검색어를 입력해주세요.**

안내를 표시한다.

빈 검색어로 검색결과를 갱신하지 않는다.

### 검색어 앞뒤 공백

자동 제거한다.

예:

`  어묵  `

→

`어묵`

---

# 10. 1차 정렬 필터

검색창 아래에 정렬 버튼을 가로로 배치한다.

Reference Image의 버튼 구조를 유지한다.

최소 다음 정렬 옵션을 제공한다.

* **추천순**
* **가격순**
* **배송비순**
* **도착 빠른순**

### 최초 진입

기본값:

**추천순**

추천순 버튼이 코레일 블루 등으로 활성화되어 있어야 한다.

다른 버튼은 흰색 또는 밝은 회색의 비활성 상태로 표시한다.

---

# 11. 정렬 인터랙션

### 추천순

기본 Mock Ranking 순으로 상품 표시

### 가격순

상품 판매가격이 낮은 순으로 정렬

### 배송비순

배송비가 낮은 상품부터 정렬

### 도착 빠른순

예상 수령시간이 빠른 상품부터 정렬

정렬 버튼을 누르면 **페이지 이동 없이 현재 상품 리스트만 즉시 재정렬**한다.

선택된 정렬 옵션은 하나만 활성화한다.

---

# 12. 배송 관련 필터

정렬 버튼 아래에 Reference Image처럼 배송 관련 조건을 **Chip / Toggle Button 형태**로 제공한다.

최소 다음 조건을 표시한다.

* **배송비 포함 가격**
* **역 픽업 가능**
* **퀵배송 연계**

Reference Image에서 사용된 아이콘을 참고한다.

예:

`✓ 배송비 포함 가격`

`✓ 🚉 역 픽업 가능`

`⚡ 퀵배송 연계`

---

# 13. 배송필터 인터랙션

배송 필터는 복수 선택 가능하도록 구현한다.

예:

사용자가

`배송비 포함 가격`

*

`역 픽업 가능`

동시에 선택 가능.

### 배송비 포함 가격 ON

상품 가격 표시를:

`상품가격 + 예상 배송비`

기준으로 비교할 수 있도록 한다.

필요하면 카드에 다음처럼 표현한다.

상품가격
20,000원

예상 배송비
3,000원

총 예상결제금액
23,000원

단, 화면이 복잡해지지 않도록 기존 Reference Image의 간결한 정보구조를 우선한다.

### 역 픽업 가능 ON

도착역에서 직접 수령 가능한 상품만 표시한다.

### 퀵배송 연계 ON

역 도착 후 퀵배송 또는 Last-mile 연계가 가능한 상품만 표시한다.

필터 변경 시 페이지 이동 없이 상품 리스트가 즉시 갱신되어야 한다.

---

# 14. 필터 선택 디자인

### 비활성

* 흰색 Background
* 밝은 회색 Border
* 회색 텍스트

### 활성

* 연한 코레일 블루 Background 또는 흰색
* 코레일 블루 Border
* 체크 아이콘
* 코레일 블루 텍스트

Reference Image처럼 현재 활성화된 조건을 사용자가 한눈에 알 수 있도록 한다.

---

# 15. 상품 카테고리 필터

배송 필터 아래에 상품 카테고리를 가로 배치한다.

Reference Image 구조를 유지한다.

최소 다음 카테고리를 사용한다.

* **전체**
* **먹거리**
* **디저트**
* **선물**
* **공예·기념품**

### 기본값

**전체**

활성화 상태.

---

# 16. 상품 카테고리 인터랙션

사용자가 카테고리를 클릭하면 현재 검색결과 중 해당 카테고리에 해당하는 상품만 표시한다.

예:

`디저트`

클릭

→ 검색어에 해당하면서 category가 디저트인 상품만 표시

`전체`

클릭

→ 다시 전체 검색결과 표시

페이지 이동 없이 현재 리스트를 갱신한다.

---

# 17. 카테고리 Scroll

모바일 화면 폭에 모든 카테고리가 들어가지 않는 경우:

**Horizontal Scroll**

방식으로 구현한다.

카테고리 버튼 자체는 작고 둥근 Pill 형태를 사용한다.

---

# 18. 검색결과 요약정보

필터 아래, 실제 상품 리스트 시작 전에 검색결과 정보를 표시한다.

Reference Image처럼 다음 형식으로 표현한다.

예:

**총 24개 상품 · "어묵" 검색결과**

검색된 결과 수는 필터 적용 시 현재 표시되고 있는 상품 개수를 반영하도록 한다.

예:

전체:

`총 24개 상품`

↓

역 픽업 가능 필터 적용:

`총 12개 상품`

---

# 19. 상품 검색결과 리스트

검색결과는 **세로형 Product Card 리스트**로 표시한다.

Reference Image와 같이:

왼쪽:

상품 이미지

오른쪽:

상품 관련 정보

구조를 사용한다.

한 화면에 약 3개의 상품 카드가 보이는 정도의 크기로 구성한다.

---

# 20. 상품 카드에 표시되는 정보

각 상품 Card에는 최소 다음 정보를 표시한다.

### 1. 지역 및 매장

상품명보다 작은 회색 텍스트

예:

**부산 · 삼진어묵 부산역점**

### 2. 상품명

크고 굵은 텍스트

예:

**어묵 선물세트 1호**

### 3. 가격

예:

**20,000원**

상품명 다음으로 강하게 강조한다.

### 4. 배송 관련 정보

상품에 따라 1~2개의 배송 Badge를 표시한다.

예:

`오늘 18:30 도착`

`역 픽업`

`배송비 무료`

`내일 도착`

`퀵배송 가능`

각 Badge는 의미에 따라 다른 배경색을 사용할 수 있다.

# 22. 상품 이미지

상품 카드 왼쪽에 정사각형 또는 Rounded Rectangle 상품 이미지를 배치한다.

Reference Image처럼:

* 일정한 이미지 크기 유지
* Rounded Corner
* 카드 전체 높이에 비해 이미지가 지나치게 작지 않게 구성

이미지가 없는 상품의 경우 Placeholder를 사용한다.

Broken Image Icon을 그대로 노출하지 않는다.

---

# 23. 배송 Badge 디자인

Reference Image에서 상품의 핵심 특징을 Badge 형태로 표시하는 방식을 반드시 유지한다.

예:

### 도착시간

`🕒 오늘 18:30 도착`

연한 Blue 계열

### 역 픽업

`🚉 역 픽업`

연한 Yellow / Orange 계열

### 배송비 무료

`배송비 무료`

연한 Green 계열

### 퀵배송

`⚡ 퀵배송 가능`

연한 Red / Pink 계열

Badge가 상품명이나 가격보다 강하게 보이지 않도록 한다.

---

# 24. 상품 카드 인터랙션

**상품 카드 전체를 클릭 가능 영역으로 처리한다.**

사용자가 상품 이미지만 눌러도 되고 상품명이나 카드의 빈 영역을 눌러도 동일하게 작동한다.

### 클릭 결과

상품 카드 클릭

→ **D3 상품 상세설명 화면으로 이동**

클릭한 상품의 정보를 D3로 전달한다.

최소:

* productId
* 상품명
* 가격
* 매장
* 이미지

등을 식별할 수 있도록 한다.

---

# 25. 정렬 + 필터 조합

사용자가 여러 조건을 동시에 사용할 수 있어야 한다.

예:

검색어:
`어묵`

정렬:
`도착 빠른순`

배송 필터:
`역 픽업 가능`

카테고리:
`선물`

이 경우:

**어묵 검색결과 중 선물 카테고리이며 역 픽업 가능한 상품을 도착시간 빠른 순으로 표시**

하도록 한다.

Mock data에 조건이 충분하지 않다면 데모가 가능하도록 데이터를 구성한다.

---

# 26. 필터 설정 초기화

필터가 여러 개 적용된 경우 전체 필터를 쉽게 해제할 수 있도록 할 수 있다.

Reference Image 우측 상단 설정 아이콘을 누르면 간단한 필터 UI를 보여주거나,

필요하면:

**초기화**

버튼을 제공한다.

단, 새로운 복잡한 Modal이나 별도 페이지를 만드는 것은 피한다.

D2 데모에 필요한 최소 동작만 구현한다.

---

# 27. 검색 결과 없음 예외상태

검색결과가 0개인 경우 빈 화면으로 두지 않는다.

중앙에 다음과 같은 Empty State를 표시한다.

### 문구

**검색 결과가 없습니다.**

보조문구:

**다른 검색어나 조건으로 다시 검색해보세요.**

가능하면:

**필터 초기화**

버튼을 제공한다.

### 클릭

필터 초기화

→ 적용된 정렬/배송/카테고리 조건을 기본 상태로 복원

검색어는 그대로 유지한다.

---

# 28. 필터 적용 후 결과 없음

검색어 자체에는 상품이 존재하지만 특정 필터 조합 때문에 결과가 없는 경우:

**선택한 조건에 맞는 상품이 없습니다.**

보조문구:

**필터 조건을 변경해보세요.**

표시

필터 초기화 버튼 제공

---

# 29. 상품 데이터 오류

상품 일부의 데이터가 누락되어도 카드 전체가 깨지지 않도록 한다.

### 이미지 없음

Placeholder

### 매장명 없음

매장명 영역 생략

### 배송정보 없음

배송 Badge 생략

### 가격정보 없음

`가격 확인 필요`

표시

---

# 30. 로딩 상태

검색조건 또는 필터를 변경한 직후 데이터가 로딩되는 상황을 표현할 필요가 있다면:

간단한 Skeleton Card 또는 Loading Indicator를 사용한다.

실제 API를 사용하지 않는 데모에서는 로딩시간을 인위적으로 길게 만들 필요가 없다.

즉시 결과를 보여줘도 된다.

---

# 31. 하단 Main Navigation

Reference Image처럼 화면 하단에 기존 코레일톡 Main Navigation을 유지한다.

기존 프로젝트의 Navigation 컴포넌트를 그대로 재사용한다.

예:

* 홈
* 승차권
* 여행
* 쇼핑
* 마이

D2에서는:

**쇼핑 활성화**

상태를 유지한다.

다른 탭을 클릭하면 기존 해당 서비스 화면으로 이동한다.

---

# 32. 화면 디자인 특징

D2는 상품 비교가 핵심이므로 **정보 가독성을 가장 우선한다.**

### 화면 전체

* 모바일 세로형
* 흰색 또는 매우 연한 회색 Background
* 코레일 Blue를 주요 Active Color로 사용
* 세로 Scroll

### 검색창

* 화면 폭 대부분 사용
* 다른 요소보다 충분히 크게 표현
* Rounded Rectangle
* 검색어가 즉시 인식되도록 함

### 정렬/필터

* 작은 Pill Button
* 여러 조건을 한눈에 비교할 수 있도록 배치
* 필요시 가로 Scroll

### 상품 카드

* 흰색
* Rounded Corner
* 밝은 Border 또는 약한 Shadow
* 카드 사이 충분한 여백

---

# 33. 정보 강조 관계

각 Product Card에서 사용자가 다음 순서로 정보를 인지하도록 한다.

1. **상품 이미지**
2. **상품명**
3. **가격**
4. **배송/수령 특징**
5. **지역 및 매장명**

단, 철도물류 접근성을 보여주는 서비스이므로:

* 오늘 도착
* 역 픽업
* 퀵배송 가능

등의 배송 특성도 쉽게 발견할 수 있도록 Badge 형태로 보여준다.

---

# 34. 스크롤 방식

### Vertical Scroll

검색결과 전체 목록

### Horizontal Scroll 가능

* 정렬 옵션
* 상품 카테고리

단, 화면 폭이 충분하다면 Reference Image처럼 한 화면에 배치해도 된다.

하단 Main Navigation이 Fixed인 경우 마지막 상품 카드가 Navigation에 가려지지 않도록 충분한 Bottom Padding을 설정한다.

# 36. Reference Image에서 변경 가능한 부분

Reference Image의 검색어는 예시로 `대전역`이 들어가 있지만, 실제 구현에서는 **D1에서 전달받은 검색어를 동적으로 표시한다.**

따라서 데모 Flow에서 D1에서:

`어묵`

을 검색했다면 D2에서는:

`어묵`

이 표시되어야 한다.

Reference Image의 레이아웃은 유지하되 상품 데이터 역시 `어묵` 검색에 자연스럽도록 변경한다.

# 37. 사용자 행동과 시스템 반응

# 38. 다음 화면

D2에서 주요 다음 화면은 다음 하나만 명확히 정의한다.

### 상품 선택

D2 검색결과

→ 원하는 상품 Card 클릭

→ **D3 상품 상세설명**

D2에서는 **D3의 화면 구성이나 세부 기능을 구현하거나 임의로 정의하지 않는다.**

클릭한 상품의 식별정보만 D3에 전달할 수 있도록 준비한다.

# 39. 구현 시 기존 컴포넌트 우선 활용

코드를 수정하기 전에 현재 프로젝트를 확인한다.

다음 요소가 이미 구현되어 있다면 새로 만들지 않는다.

* Header
* Bottom Navigation
* Search Input
* Product Card
* Filter Chip
* Badge
* Button
* Loading UI
* Empty State
* 이미지 Placeholder

D1에서 이미 Search Input이나 상품 관련 Mock Data를 만들었다면 D2에서 그대로 재사용한다.

동일 기능을 중복 구현하지 않는다.

# 40. D1과의 디자인 연결

D1과 D2가 서로 다른 앱처럼 보이지 않아야 한다.

반드시 다음을 동일하게 유지한다.

* Font
* 코레일 Blue
* Card Radius
* Icon Style
* Search Input Style
* Main Navigation
* Spacing System
* Background Color

특히 D1 검색창에서 D2 검색결과로 넘어왔을 때 **같은 쇼핑서비스 안에서 자연스럽게 화면이 전환되는 느낌**이어야 한다.

# 42. 작업 범위 제한

**이번 작업에서는 D2 검색결과 화면만 구현한다.**

D2와 직접 연결되는 기존 화면은 활용하되 다른 화면을 임의로 새로 설계하지 않는다.

허용되는 연결:

* 이전 화면: D1
* 상품 클릭 후: D3

D3의 상세 UI나 그 이후 페이지는 이번 작업 범위에 포함하지 않는다.

기존 프로젝트의 정상 기능을 삭제하거나 대규모 리팩터링하지 않는다.

D2 구현에 필요한 검색·정렬·필터·Mock Data 및 화면 연결만 최소 범위로 추가한다.
