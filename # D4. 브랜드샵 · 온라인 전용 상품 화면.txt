# D4. 브랜드샵 · 온라인 전용 상품 화면 구현

현재 구현 중인 코레일 지역상품 쇼핑 서비스에 **D4. 브랜드샵 · 온라인 전용 상품 화면**을 구현해줘.

이 화면은 코레일과 제휴를 맺은 특정 업체가 **온라인으로 판매하는 상품들을 한 번에 둘러보고 장바구니에 담을 수 있는 브랜드샵 페이지**다.

첨부한 D4 레퍼런스 이미지를 전체적인 레이아웃과 정보 배치의 기준으로 참고해줘.

이 화면의 핵심 사용자 흐름은 다음과 같다.

**브랜드샵 진입 → 업체 정보 확인 → 온라인 주문 및 철도배송 안내 확인 → 상품 둘러보기 → `+` 버튼으로 상품 담기 → ‘담은 상품 보기’**

레퍼런스를 그대로 복사하기보다 기존 D1~D3에서 사용한 코레일 쇼핑 UI와 자연스럽게 이어지도록 구현해줘.

---

# 1. D4 진입 구조

기존 화면에서 특정 업체의

**브랜드샵**

또는

**이 가게 상품 보기**

버튼을 누르면 D4로 이동하도록 연결해줘.

예:

D3 상품 상세페이지

**성심당 대전역점
이 가게 상품 보기 >**

클릭

→ 해당 업체의 D4 브랜드샵 화면

형태로 연결할 수 있다.

route 예시는 다음과 같이 사용할 수 있다.

`/shop/brand/:storeId`

브랜드샵에 들어오면 선택한 업체에 따라

* 업체명
* 위치
* 판매 상품
* 상품 가격
* 상품 이미지

등이 달라져야 한다.

모든 업체가 동일한 상품을 보여주는 방식으로 구현하지 말아줘.

---

# 2. 전체 화면 구조

모바일 약 360~430px 너비를 기준으로 구현한다.

화면은 다음 순서로 구성한다.

1. 상단 뒤로가기
2. 업체명
3. 업체 위치
4. 철도배송 안내
5. 상품 개수 및 정렬
6. 온라인 판매 상품 리스트
7. 담은 상품 보기 버튼

상품이 많아질 경우 화면 전체가 **세로 스크롤 가능**해야 한다.

---

# 3. 상단 업체명

화면 상단에는 현재 브랜드샵의 업체명을 가장 먼저 표시한다.

예:

# 삼진어묵 부산역점

레퍼런스처럼 화면 중앙 또는 상단에서 명확하게 업체명이 보이도록 한다.

왼쪽에는 뒤로가기 버튼을 배치한다.

뒤로가기 버튼을 누르면 이전 화면으로 돌아간다.

---

# 4. 업체 위치

업체명 아래에는 업체 위치 정보를 작은 보조 텍스트로 표시한다.

예:

📍 **부산역 3번 출구 도보 2분**

또는

📍 부산광역시 동구 중앙대로 206

형태로 구성할 수 있다.

위치는 상품보다 중요도가 낮기 때문에 업체명보다 작은 텍스트로 표현한다.

---

# 5. 철도배송 안내 영역

업체 정보 아래에는 **이 브랜드샵의 상품을 코레일 철도배송으로 받을 수 있다는 안내 영역**을 만들어줘.

이 부분은 일반적인 온라인 브랜드숍과 코레일 쇼핑 서비스를 구분하는 중요한 요소다.

첨부한 레퍼런스처럼 **연한 코레일 블루 배경의 rounded card** 형태로 구성한다.

예:

🚄

**앱에서 주문하면 원하는 곳으로 철도배송 받을 수 있어요**

또는

**온라인 주문 상품도 코레일 철도배송으로 빠르게 받아보세요.**

필요하면 아래에 작은 설명을 추가한다.

예:

**역 픽업 또는 연계배송을 선택할 수 있습니다.**

안내 영역은 지나치게 큰 광고 배너처럼 만들지 않고 상품 목록 시작 전에 자연스럽게 안내하는 수준으로 구성한다.

---

# 6. 상품 목록 헤더

철도배송 안내 아래에는 현재 업체가 판매하는 온라인 상품 개수를 표시한다.

예:

## 전체 상품 3

숫자는 포인트 컬러를 적용해도 된다.

오른쪽에는 레퍼런스 이미지처럼 간단한 정렬 기능을 추가한다.

기본값:

**인기순 ▼**

클릭하면 다음과 같은 옵션을 사용할 수 있다.

* 인기순
* 낮은 가격순
* 높은 가격순

시연용 프로토타입이므로 간단한 dropdown 또는 bottom sheet 형태로 구현해도 된다.

정렬을 변경하면 실제 상품 배열의 순서도 변경되도록 한다.

---

# 7. 상품 리스트 기본 구조

업체에서 판매하는 상품들은 **세로 리스트 형태**로 표시한다.

레퍼런스 이미지의 상품 행 구조를 반드시 유지한다.

각 상품은 다음과 같이 구성한다.

**왼쪽**

상품 이미지

**가운데**

상품명
가격

**맨 오른쪽**

원형 `+` 버튼

형태다.

상품 하나마다 충분한 높이를 확보하고 상품 사이에는 divider 또는 여백을 사용해서 구분한다.

---

# 8. 상품 이미지

각 상품의 왼쪽에는 정사각형 또는 rounded rectangle 형태의 상품 이미지를 배치한다.

예:

약 88~100px 정도의 영역

이미지 모서리는 둥글게 처리한다.

실제 상품 이미지가 없다면 시연용 placeholder 이미지를 사용할 수 있지만, 각 상품이 구분될 수 있도록 서로 다른 이미지를 사용한다.

---

# 9. 상품명

상품 이미지 오른쪽 상단에는 상품명을 표시한다.

예:

**어묵 선물세트 1호**

상품명은 가격보다 위에 표시한다.

글씨는 충분히 강조하되 한 상품명이 지나치게 여러 줄을 차지하지 않도록 최대 2줄 정도로 제한한다.

---

# 10. 상품 가격

상품명 아래에는 가격을 표시한다.

예:

**20,000원**

가격은 굵은 글씨로 표시한다.

레퍼런스처럼 상품명과 가격이 상품 정보의 핵심이 되도록 한다.

---

# 11. `+` 상품 담기 버튼

각 상품 행의 가장 오른쪽에는 레퍼런스 이미지처럼 **원형 `+` 버튼**을 배치한다.

예:

`＋`

버튼 배경은 연한 블루,

`+` 아이콘은 코레일 블루로 표현한다.

이 버튼은 단순한 UI가 아니라 실제 장바구니 기능과 연결해야 한다.

---

# 12. `+` 버튼 동작

사용자가 특정 상품의 `+` 버튼을 누르면 해당 상품을 현재 브랜드샵의 임시 장바구니에 추가한다.

저장해야 할 정보는 최소한 다음과 같다.

* productId
* productName
* storeId
* price
* quantity
* image

상품이 정상적으로 추가되었음을 사용자가 알 수 있도록 간단한 인터랙션을 제공한다.

예:

`+`

클릭

→ 버튼이 잠시 체크 아이콘으로 변경

또는

**어묵 선물세트를 담았습니다.**

라는 작은 toast 표시

또는

하단의 ‘담은 상품 보기’에 상품 수 표시

등의 방식으로 구현한다.

---

# 13. 같은 상품을 다시 누르는 경우

이미 담긴 상품의 `+` 버튼을 다시 누르면 해당 상품의 수량을 1 증가시키는 방식으로 구현해줘.

예:

처음 클릭

→ 어묵 선물세트 × 1

다시 클릭

→ 어묵 선물세트 × 2

담긴 상품 개수와 총 금액도 이에 맞춰 업데이트한다.

---

# 14. 상품 클릭

상품의 이미지 또는 상품명 영역 자체를 클릭하면 해당 상품의 D3 상품상세 화면으로 이동하도록 연결해줘.

즉,

`+` 버튼

→ 바로 장바구니에 추가

상품 카드 클릭

→ D3 상세페이지 확인

으로 동작을 구분한다.

예:

**프리미엄 어묵세트**

클릭

→ `/shop/product/:productId`

→ D3 제품상세설명

---

# 15. 시연용 상품 데이터

첨부한 레퍼런스를 참고해서 대표 업체로

**삼진어묵 부산역점**

을 사용할 수 있다.

예시 상품:

### 상품 1

상품명: 어묵 선물세트 1호
가격: 20,000원
카테고리: 선물

### 상품 2

상품명: 프리미엄 어묵세트
가격: 28,000원
카테고리: 선물

### 상품 3

상품명: 종합 선물세트
가격: 35,000원
카테고리: 선물

시연 시 스크롤도 확인할 수 있도록 필요하다면 5~8개의 상품 mock data를 추가해도 된다.

예:

* 부산어묵 실속세트 / 18,000원
* 어묵탕 홈세트 / 24,000원
* 부산역 한정 선물세트 / 32,000원

---

# 16. 담은 상품 보기

상품 목록의 아래에는 레퍼런스 이미지처럼 큰 CTA 버튼을 배치한다.

버튼 문구:

**🛒 담은 상품 보기**

버튼은 화면 너비 대부분을 사용하는 큰 rounded rectangle 형태로 구성한다.

진한 코레일 블루 배경과 흰색 텍스트를 사용해서 화면에서 가장 강한 CTA가 되도록 한다.

예:

**🛒 담은 상품 보기**

또는 상품이 담겼다면

**🛒 담은 상품 보기 · 3개**

처럼 현재 담은 상품 수를 함께 표시해도 된다.

---

# 17. 담은 상품 보기 동작

버튼을 클릭하면 사용자가 현재 업체에서 담은 상품을 확인할 수 있는 장바구니 또는 주문 준비 화면으로 이동한다.

예:

D4

→ 담은 상품 보기

→ 장바구니 화면

아직 별도의 장바구니 페이지가 구현되지 않았다면 간단한 임시 화면이라도 만들어 navigation이 정상 동작하도록 한다.

장바구니에는 D4에서 사용자가 `+` 버튼으로 선택한 상품만 표시되어야 한다.

---

# 18. 장바구니가 비어 있는 상태

아직 아무 상품도 선택하지 않았다면 ‘담은 상품 보기’ 버튼을 비활성화 상태로 만들어도 된다.

예:

상품 0개

→ 버튼을 연한 회색 또는 연한 블루 상태로 표시

상품 1개 이상

→ 진한 코레일 블루 CTA로 활성화

또는 항상 클릭 가능하게 하고 클릭했을 때

**담은 상품이 없습니다.**

empty state를 표시해도 된다.

현재 프로젝트 UI 패턴에 더 자연스러운 방법을 선택한다.

---

# 19. 장바구니 상태 공유

D3의 장바구니 기능과 D4의 `+` 버튼 기능이 서로 다른 장바구니를 만들지 않도록 한다.

가능하면 동일한 cart state 또는 store를 사용한다.

예:

D3에서 상품 A를 장바구니에 추가

*

D4에서 상품 B를 `+` 버튼으로 추가

→ 동일한 장바구니에서 상품 A와 상품 B를 확인

할 수 있도록 한다.

기존 프로젝트에 Context, Zustand, Redux 또는 다른 상태관리 방식이 있다면 해당 방식을 재사용한다.

---

# 20. mock data 구조

업체와 상품 데이터는 페이지 JSX에 직접 반복 작성하지 말고 별도 mock data로 관리한다.

예:

```text
store
- id
- name
- region
- locationText
- description
- railDeliveryAvailable
- products

product
- id
- storeId
- name
- price
- image
- category
- popularity
```

D3에서 사용하는 기존 상품 mock data가 있다면 중복 데이터를 새로 만들지 말고 해당 데이터를 재사용하거나 확장한다.

---

# 21. 시연용 업체 예시

대표 화면은 다음 데이터로 구현해줘.

업체:

**삼진어묵 부산역점**

위치:

**부산역 3번 출구 도보 2분**

철도배송:

**가능**

안내 문구:

**앱에서 주문하면 원하는 곳으로 철도배송 받을 수 있어요**

상품:

1. 어묵 선물세트 1호 / 20,000원
2. 프리미엄 어묵세트 / 28,000원
3. 종합 선물세트 / 35,000원

레퍼런스 이미지와 비슷한 정보 밀도로 먼저 구현해줘.

---

# 22. 디자인 방향

첨부한 D4 레퍼런스에서 다음 요소를 특히 참고한다.

### 업체명

상단에서 명확하게 표시

### 위치

핀 아이콘과 함께 작은 보조정보로 표시

### 철도배송 안내

연한 블루 배경의 rounded card

### 상품

세로 리스트 형태

각 상품은

**상품 이미지 | 상품명 + 가격 | `+`**

구조로 구성

### `+` 버튼

작은 원형 버튼

연한 블루 배경

코레일 블루 아이콘

### 담은 상품 보기

화면 하단에 큰 코레일 블루 CTA 버튼

전체적인 스타일은 기존 D1~D3와 동일하게

* 흰색 중심 배경
* 코레일 블루 포인트 컬러
* rounded UI
* 과도하지 않은 그림자
* 충분한 여백
* 모바일 커머스 UI

를 유지한다.

---

# 23. D4 최종 정보 구조

최종적으로 사용자가 D4에 들어왔을 때 다음 순서로 보여야 한다.

**←　　　　　삼진어묵 부산역점**

↓

**📍 부산역 3번 출구 도보 2분**

↓

**🚄 앱에서 주문하면
원하는 곳으로 철도배송 받을 수 있어요**

↓

**전체 상품 3　　　　　　　　　인기순 ▼**

# 25. 구현 완료 기준

다음 조건을 모두 충족하는지 확인해줘.

1. 브랜드샵 또는 ‘이 가게 상품 보기’를 누르면 D4로 이동한다.
2. 선택한 업체에 따라 D4 업체명이 달라진다.
3. 업체 위치가 표시된다.
4. 철도배송 가능 안내가 표시된다.
5. 현재 업체가 판매하는 온라인 상품만 표시된다.
6. 전체 상품 개수가 표시된다.
7. 상품을 인기순 또는 가격순으로 정렬할 수 있다.
8. 각 상품 왼쪽에 이미지가 표시된다.
9. 상품명이 표시된다.
10. 가격이 표시된다.
11. 각 상품 오른쪽에 `+` 버튼이 있다.
12. `+` 버튼을 누르면 실제 장바구니에 상품이 담긴다.
13. 같은 상품의 `+`를 다시 누르면 수량이 증가한다.
14. 상품 카드 자체를 누르면 D3 상품 상세화면으로 이동한다.
15. 목록 아래에 ‘담은 상품 보기’ 버튼이 있다.
16. 담은 상품 수가 장바구니 상태와 연동된다.
17. ‘담은 상품 보기’를 누르면 장바구니 화면으로 이동한다.
18. D3의 장바구니와 동일한 cart state를 사용한다.
19. 상품이 많아지면 화면을 세로 스크롤할 수 있다.
20. 모바일 약 360~430px에서 UI가 깨지지 않는다.
21. 첨부한 D4 레퍼런스 이미지와 전체적인 정보 구조가 유사하다.

새 프로젝트를 만들지 말고 **현재 D1~D3가 구현되어 있는 코레일 쇼핑 프로젝트 내부에서 이어서 구현**해줘.

작업 시작 전에 기존의

* router
* product mock data
* store data
* cart state
* D3 상품 상세페이지
* global style
* icon library

를 먼저 확인한다.

특히 D3에서 이미 장바구니 로직을 구현했다면 별도의 장바구니 상태를 새로 만들지 말고 반드시 재사용해줘.

기존 D1~D3 화면과 다른 정상적인 화면은 불필요하게 수정하지 말아줘.

구현 완료 후 변경된 파일을 확인하고 build 또는 실행 과정에서 오류가 없는지까지 검사해줘.
